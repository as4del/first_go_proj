# LinkForge

LinkForge — учебный backend-сервис сокращения ссылок на Go. Проект создан для изучения Go и архитектуры backend-приложений при переходе с C++ и userver.

Пользователь может зарегистрироваться, войти в аккаунт, создать короткую ссылку с собственным кодом и посмотреть свои ссылки. При открытии короткого адреса сервер перенаправляет на исходный сайт. Для работы с сервисом есть веб-интерфейс.

## Авторство

Проект, включая backend, работу с PostgreSQL, API, сессии и cookie, разработан автором самостоятельно. Исключение — фронтенд: он создан ИИ-агентом **OpenAI Codex**.

## Технологии

- Go и Gin — HTTP-сервер и маршрутизация.
- PostgreSQL 17 — хранение пользователей и ссылок.
- `pgx/v5/pgxpool` — общий пул соединений с базой данных.
- `gin-contrib/sessions` и cookie store — пользовательские сессии.
- `godotenv` — загрузка локальных переменных окружения из `.env`.
- Docker Compose — запуск PostgreSQL и Adminer.
- HTML, CSS и JavaScript — фронтенд без сборки и npm.

Go-модуль пока называется `awesomeProject`.

## Структура

```text
main.go               Запуск сервера, настройка пула, сессий и маршрутов
handlers/             HTTP-обработчики, JSON и работа с сессией
repository/           SQL-запросы и работа с PostgreSQL
structs/              Модели данных
frontend/             Веб-интерфейс
init.sql              Начальная схема базы данных
docker-compose.yaml   PostgreSQL и Adminer
```

Сервер создаёт один общий пул соединений. Репозиторий хранит указатель на пул, а обработчики — ссылку на репозиторий. SQL находится в `repository`, HTTP-логика — в `handlers`.

## Локальный запуск

### 1. Подготовить окружение

Понадобятся Go с поддержкой версии, указанной в `go.mod` (сейчас `1.27.3`), Docker и Docker Compose. На macOS можно использовать Docker Desktop; перед запуском контейнеров он должен работать.

Все команды ниже выполняются из корня проекта.

### 2. Создать `.env`

Создай файл `.env` рядом с `main.go`:

```dotenv
POSTGRES_PASSWORD=replace_with_local_db_password
DATABASE_URL=postgres://linkforge:replace_with_local_db_password@localhost:5432/linkforge?sslmode=disable
SECRET_CODE=replace_with_your_random_session_secret
```

Замени значения-заглушки своими:

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_PASSWORD` | Пароль пользователя PostgreSQL `linkforge`; используется Docker Compose. |
| `DATABASE_URL` | Строка подключения Go-приложения к базе. Пароль должен совпадать с `POSTGRES_PASSWORD`. |
| `SECRET_CODE` | Секрет для подписи сессионных cookie. |

Для генерации случайного секрета можно выполнить:

```bash
openssl rand -hex 32
```

Скопируй результат в `SECRET_CODE`. Сохраняй этот секрет между перезапусками, иначе существующие cookie перестанут проходить проверку.

Если пароль БД содержит специальные символы URI, их нужно закодировать в `DATABASE_URL`. Настройка `sslmode=disable` в примере предназначена для локального запуска.

**Не публикуй `.env` и не добавляй его в Git.** Примеры выше не содержат действующих секретов. Сейчас приложение ожидает наличие `.env`: при ошибке его загрузки запуск прекращается.

### 3. Запустить базу и Adminer

```bash
docker compose up -d
docker compose ps
```

Дождись, пока PostgreSQL станет `healthy`. При необходимости посмотреть его логи:

```bash
docker compose logs postgres
```

База сохраняется в Docker volume `postgres_data`. Скрипт `init.sql` выполняется при первой инициализации пустой базы. Изменение `init.sql` не обновляет уже существующие таблицы; изменение пароля в `.env` также не меняет пароль пользователя в ранее созданной базе автоматически.

### 4. Запустить Go-сервис

В отдельном терминале из корня проекта:

```bash
go mod download
go run .
```

Backend запускается на порту `8080`. Рабочая папка важна: относительно неё приложение ищет `.env` и файлы фронтенда.

### 5. Открыть сайт

Перейди на [http://localhost:8080](http://localhost:8080).

Зарегистрируй аккаунт или войди в существующий, создай ссылку и открой её из списка. Короткий адрес выглядит так:

```text
http://localhost:8080/get/my-link
```

HTML и API обслуживает один Gin-сервер. Открывать `frontend/index.html` как отдельный файл не нужно. Используй один и тот же адрес сервера: cookie для `localhost` и `127.0.0.1` различаются.

## Как посмотреть базу локально

Открой [Adminer — http://localhost:8081](http://localhost:8081) и заполни форму:

| Поле | Значение |
| --- | --- |
| Система | PostgreSQL |
| Сервер | `postgres` |
| Пользователь | `linkforge` |
| Пароль | Значение `POSTGRES_PASSWORD` из твоего `.env` |
| База данных | `linkforge` |

Здесь сервер — `postgres`, потому что Adminer подключается из контейнера через сеть Docker Compose. Для программы на твоём компьютере адрес БД — `localhost:5432`.

В Adminer доступны таблицы `users` и `links`. Например, в разделе SQL можно посмотреть ссылки:

```sql
SELECT id, username, short_code, original_url, created_at
FROM links
ORDER BY created_at DESC;
```

Другой способ — открыть PostgreSQL-консоль в контейнере:

```bash
docker compose exec postgres psql -U linkforge -d linkforge
```

Для выхода из `psql` введи `\q`.

## API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/new_user` | Регистрация: JSON с `username`, `email`, `password`. |
| `POST` | `/login` | Вход: JSON с `username`, `password`. |
| `GET` | `/logout` | Выход из аккаунта. |
| `GET` | `/api/me` | Проверка сессии: имя пользователя или `401 Unauthorized`. |
| `POST` | `/new_url` | Создание ссылки: JSON с `short`, `original`; нужна сессия. |
| `GET` | `/url_for_user` | Ссылки текущего пользователя; нужна сессия. |
| `GET` | `/get/:name` | Перенаправление по короткому коду, статус `302 Found`. |

Регистрация и вход сохраняют пользователя в сессии. Браузер получает cookie `main_ses` и отправляет её в последующих запросах. Фронтенд проверяет авторизацию через `/api/me`; имя пользователя для новой ссылки backend берёт из сессии.

Локальная cookie настроена с `HttpOnly`, `SameSite=Lax` и сроком действия один час. `Secure=false` позволяет использовать её при локальном HTTP-запуске.

## Остановка

Останови Go-сервис сочетанием `Ctrl+C`. Контейнеры можно остановить командой:

```bash
docker compose down
```

Эта команда сохраняет volume с данными БД.

## Текущий статус

Проект учебный и развивается. Сейчас пароль записывается напрямую в поле `password_hash` и сравнивается с ним при входе: хеширование ещё не реализовано. Для тестирования используй отдельные тестовые пароли. Текущая конфигурация рассчитана на локальную разработку.
